
## 五段光照时间（黄金 / 民用 / 航海 / 天文 / 蓝调）

`SolarCalculator` 现在把太阳高度角切成五段，每段给出当日「落在带内」的时间区间（最多两段：上午一段、傍晚一段）：

| 时段 | 太阳高度 |
|---|---|
| 黄金时刻 | −0.833° → +6° |
| 民用晨昏 | −6° → −0.833° |
| 航海晨昏 | −12° → −6° |
| 天文晨昏 | −18° → −12° |
| 蓝调时刻 | −6° → −4°（民用晨昏内部的一小段） |

高纬会退化，`LightBand.intervals` 因此是列表而不是一对可空值：

- **极夜**（太阳最高也在地平线下）：只剩「升到 low 界 → 又降回 low 界」一整个区间，例如奥斯陆 12-21 民用晨昏 09:31–13:54。
- **白夜 / 午夜太阳**（太阳从不低于 lower 界）：带内时间挤在午夜前后，是一段跨零点的区间，例如雷克雅未克 06-21 民用晨昏 00:04–02:55。
- 带内时间根本没有：空列表，UI 显示「—」。

`compare.py` 与 astral 的 `dawn/dusk(depression)`、`time_at_elevation(6, …, with_refraction=False)` 对表（几何高度角，与项目定义一致），并同样实现两级退化，所以能区分「时间差」和「该不该出现」。

当前结果：**802 个对照值，5 处不符，全部在麦克默多站（77.85°S）**——那里太阳贴地平线掠射，0.1° 的建模差异就是 8–9 分钟；其中两处是切点附近 astral 认为某高度角不可达、本项目认为可达。其余 9 个地点 × 5 个日期全部在 3 分钟内。

`stubs/` 里是离线 bench 用的 `R` 与 `androidx.annotation.StringRes` 桩：`LightPeriod` 带 `@StringRes`，脱离 Android SDK 编译不过。
